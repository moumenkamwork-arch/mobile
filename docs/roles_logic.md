# المنطق الخاص بصلاحيات وأنواع الحسابات (Roles / Account Types)

في تطبيق **Promoo**، نظام الحسابات مبني على أساس نوع الحساب `account_type` الذي يتم اختياره عند التسجيل. الباك إند (Supabase + Node.js) يفرض حماية صارمة على مستوى الـ API لكل نوع حساب.

الأنواع الأربعة المتاحة في قاعدة البيانات هي:

1. `user` (مستخدم عادي)
2. `influencer` (مؤثر)
3. `service_provider` (مقدم خدمة)
4. `company` (شركة)

---

## 1. تفصيل الصلاحيات من الباك إند (Backend Rules)

بحسب الكود الموجود في `promo_backend/src/routes/`، تم تطبيق وسيط حماية `requireAccountType` يحدد من يحق له إضافة أو إدارة الموارد:

### أ) العروض (Offers)

- **من يستطيع الإضافة:** `company` و `service_provider` و `influencer`. ✅ **مطبّق فعلياً بالكود** (2026-07-23) — `requireAccountType(['company', 'service_provider', 'influencer'])` على `POST /offers` (`offer.routes.ts`)، ومرآته بالموبايل `AccountCapabilities.canAddOffer`.
- **المنطق:** العروض (مثل العروض المميزة وعروض اليوم) تتيح للشركات تقديم خصومات المنتجات، ولمزودي الخدمات تقديم خصومات على خدماتهم، وللمؤثرين تقديم باقات أو عروض ترويجية بدل الإعلانات (بعد حذف Ads، شوف قسم د). (المستخدم العادي `user` فقط مستبعد).

### ب) الخدمات (Services)

- **من يستطيع الإضافة:** `service_provider` و `company` فقط.
- **المنطق:** الخدمات المعروضة في قسم Services (مثل التصوير، البرمجة، التصميم) مخصصة فقط لأصحاب المهن والشركات.

### ج) المقاعد (Seats) بصفحة الـ Influencer

- **من يستطيع رؤية الصفحة:** `influencer` و `company`.
- **من يستطيع الحجز:** `influencer` فقط.
- **المنطق:** المؤثرون يحجزون هذه المقاعد ليعرضوا أنفسهم. الشركات يجب أن تتمكن من رؤية هذه الصفحة لاختيار المؤثرين والتعاقد معهم. لا يمكن لشركة أو مستخدم عادي أن يشتري مقعد "مؤثر".

### د) الإعلانات (Ads) — _[حُذفت من الموبايل بالكامل — 2026-07-23]_

- **الخلفية:** التصميم الأصلي يلي أعطاه الزبون (Prototype) ما كان فيه أصلاً غير **عروض (Offers)** و**خدمات (Services)** — الـ "Ads" ميزة اتبنت بمرحلة سابقة زيادة عن نطاق التصميم الأصلي، واكتُشف الالتباس لما تبيّن إنو شاشة "Add New Offer" الأصلية بالتصميم القديم كانت موصولة غلط لمسار الإعلان.
- **القرار:** ✅ **حُذفت كل آثار الإعلان من كود الموبايل بالكامل** — لا شاشة، لا route، لا entity، لا repository، لا ذكر بـ Home/Search/My Listings/Reports/الحظر. الباك إند تُرك **بلا أي تعديل أو حذف** (جدول `ads`، `ad.service.ts`، `ad.routes.ts`، إلخ باقين تماماً متل ما كانوا) تحسباً لإعادة إحياء الميزة بـ v2 لو احتاج المشروع.
- **التعويض للمؤثر:** `influencer` كان الوحيد يلي دوره الأساسي بالنشر مرتبط بـ Ads (`canAddAd`) — بعد الحذف صار عندو نفس صلاحية العروض (`canAddOffer` توسّعت لتشمله، شوف قسم أ فوق) فما ضل بلا أي خيار نشر.
- **التفاصيل الكاملة:** `promo_mobile/docs/MEMORY_BANK.md` §5 (إدخال 2026-07-23).

### هـ) كأس المتصدرين (Cup / Leaderboard)

- **من يظهر فيه:** `company`، `influencer`، و `service_provider` فقط.
- **المنطق:** المستخدم العادي `user` لا يظهر أبداً في قائمة المتصدرين (التي تعتمد على عدد المتابعين). هو موجود فقط للتصفح والشراء.

## 2. كيف يجب أن يعمل اللوجيك في الموبايل (Frontend Implementation)

لأن الباك إند سيقوم برفض (HTTP 403 Forbidden) أي طلب يخالف الصلاحيات المذكورة أعلاه، يجب على واجهة الموبايل أن تتفاعل برمجياً مع الـ Role الخاص بالمستخدم لتوفير تجربة مستخدم (UX) ممتازة وتجنب رسائل الخطأ:

### عند تسجيل الدخول (Login / Auth)

- يقوم التطبيق بحفظ بيانات المستخدم `profile` ضمن الـ State (Riverpod)، والتي تتضمن حقل `account_type`.

### التغييرات المطلوبة في واجهة المستخدم (UI/UX)

1. **قائمة الملف الشخصي (Profile Tab):**
   - خيار **"إضافة عرض جديد (Add New Offer)"**: يُعرض للحسابات التجارية والمؤثرين والمزودين (`company` / `influencer` / `service_provider`) ويُخفى فقط للمستخدم العادي `user`.
   - خيار **"إضافة إعلان جديد (Add New Ad)"**: ✅ **محذوف بالكامل** (مو مخفي فقط) — الشاشة والـ route والـ repository كلهم انمسحوا من كود الموبايل. `influencer` صار يستخدم "إضافة عرض جديد" بدلاً منه.
   - خيار **"إضافة خدمة جديدة"**: يُعرض فقط لـ `service_provider` و `company`.

2. **صفحة المؤثرين (Influencer Seats):**
   - زر **"Book Seat"** أو "حجز مقعد":
     - إذا كان المستخدم `influencer` → يكمل لصفحة الحجز (Checkout).
     - إذا لم يكن مؤثر → يظهر له إشعار (Toast/Snackbar): "هذه الميزة مخصصة للمؤثرين فقط".

3. **صفحة المتصدرين (Leaderboard):**
   - لا تتطلب تغييراً في الفرونت، الباك إند سيقوم تلقائياً بتصفية المستخدمين العاديين، ولكن يمكن إضافة فلتر (Tabs) ليسمح للمستخدم برؤية متصدري الشركات لوحدهم، والمؤثرين لوحدهم.

4. **شريط التنقل السفلي (Bottom Navigation Bar):**
   - للمستخدم العادي (`user`) ومقدم الخدمة (`service_provider`): يتكون من 5 أزرار (الرئيسية، العروض، المتصدرين، الخدمات، الحساب).
   - للشركة (`company`) والمؤثر (`influencer`): يتوسع برمجياً ليصبح **6 أزرار** (يتم إضافة زر "مقاعد المؤثرين" بجانب "العروض" بشكل ديناميكي دون التضحية بأي منهما).

### الخلاصة للمرحلة الثانية (Integration Phase):

كل هذه القواعد تم بناؤها وتطبيقها بالكامل في الباك إند. خلال مرحلة الربط، سنقوم ببرمجة الواجهة لتقرأ قيمة `account_type` الخاصة بالمستخدم الذي قام بتسجيل الدخول، وبناءً عليها سنقوم بإظهار أو إخفاء الأزرار المذكورة.
