## 2. إنشاء خطتين للتخطيط (بمجلد `promo_mobile/docs/`)

### أ) `v2_deferred_scope.md`
ملف يوثق **كل شي مؤجل لـ v2** أو **مخفي بـ v1**، مقسّم لمجموعات:
- **Auth**: تأجيل كل شي إلا تسجيل الدخول/التسجيل بالإيميل (OTP، نسيت كلمة السر، Google/Apple/Facebook، تسجيل بالهاتف، حذف الحساب).
- **Payments/Stripe**: تأجيل كل الدفع (الاشتراكات، حجز المقاعد بالفعل، باقات المحتوى).
- **Notifications**: الميزة كاملة مؤجلة (بما فيها FCM/push).
- **Social engagement**: تقييمات، لايكات، تعليقات، مشاركة — ما في دعم بالباك إند أصلاً.
- **Facebook login**: الباك إند ما دعمه من الأساس.
- **حقول مخفية**: promo_code، terms، best_price، الموقع/الخريطة بالعروض.

لكل عنصر: الـ endpoint يلي رح يتربط فيه لاحقاً + شو بالضبط سلوك v1 (مخفي / عرض فقط بدون تفعيل / عنصر بصري بس).

### ب) `build_plan.md`
الخطة الرئيسية يلي رح "نأشر عليها ✅" مع بعض كل ما نخلص خطوة:
- **Phase A** — تكملة الفرونت إند بالكامل بحيث يطابق تصميم الـ MVP الأصلي بالضبط (بيكسل بالبيكسل)، على بيانات وهمية (mock)، **من غير أي ربط بالباك إند**. فيها checklist لكل شاشة (A0 لـ A22): Login، Register، Home، Services، Influencer/Seats، Cup، Profile (وكل شاشاته الفرعية متل Edit Profile وAdd New Offer وAdd New Ad و Packages)، Search، Chat، Notifications.
- **Phase B** — جدول من 15 صف يوضح قرارات ربط الباك إند لاحقاً (الباكجات، سعة المقاعد، الاشتراكات مؤجلة، ترتيب الشريط، الحقول المخفية، إضافة عرض/إعلان، متابعة/محفوظات/تعديل بروفايل، رفع صور، الكاتيجوريز، تسجيل الدخول، حفظ التوكن، رابط الـ API).
