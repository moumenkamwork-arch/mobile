# Promoo Mobile — ملخص العمل الكامل (من أول مهمة بعد الخطة حتى إعادة الضبط)

> يوثّق هذا الملف **كل ما تم** على `promo_mobile` في هذه الجولة، بالترتيب الزمني، من أول مهمة أُعطيت بعد اعتماد الخطة (تدقيق الـ Light Mode) وصولاً إلى إعادة ضبط التطبيق لحالة **frontend-only**.
>
> التاريخ: 2026-07-09 · الحالة النهائية: **frontend-only، بيانات محلية، بلا طبقة شبكة** · **160 اختبار يمرّ** · analyze نظيف.

---

## المرحلة 1 — تدقيق وإصلاح الـ Light Mode + إصلاح التنقّل للخلف + جولة UX

**المطلوب:** تدقيق كامل الواجهة؛ الـ Dark Mode مرجع صحيح، والـ Light Mode مكسور (ألوان/تباين غير متّسق) → إصلاحه ليطابق جودة الدارك بكل شاشة، مع نظام ألوان موحّد (باستخدام `frontend-design` skill). + تدقيق UX شامل، والأولوية: **زر الرجوع مكسور** (يجب أن يتبع الـ stack خطوة‑خطوة، داخلي ونظام).

**ما تم:**
- **نظام ألوان بالثيم:** حُوّل `AppColors` إلى `AppThemeColors` (ThemeExtension) بباليتين — `dark` (المرجع، بلا أي تغيير بصري) و`light` ("حبر على ورق": ورق دافئ، حبر داكن، تباين AA). أُضيف **token `accent`** (أصفر‑كحبر: أصفر بالدارك، ذهبي داكن `#7A6900` بالفاتح). الوصول عبر `context.colors`.
- **سويب ~460 مرجع لون** مكتوب يدوياً عبر ~70 ملف إلى tokens.
- **الرجوع خطوة‑خطوة:** `BackInterceptorRegistry` (`lib/routing/back_interceptors.dart`) + شريط رجوع لطبقة نتائج الخدمات؛ استبدال `context.go` بـ `push` بشاشات التفاصيل؛ منطق التبويبات (غير Home → Home → ضغطتين للخروج)؛ إصلاح حلقة الـ auth.
- **UX:** حفظ الثيم عبر `flutter_secure_storage`، توست الخروج بالـ tokens، مؤشرات التحديث/التركيز/الحالات.

**التحقق:** 192 اختبار · analyze نظيف · تحقّق بصري حيّ للثيمين.

## المرحلة 2 — توسيع الثيم للكروم كامل (Header / Bottom nav / Auth)

**المطلوب:** الهيدر والفوتر (البار السفلي) وشاشات Login/Register كانت مقفولة على الدارك → طبّق الفاتح عليها كمان (نفس الـ skill). + حلّ مشكلة اللوغو الأصفر على خلفية فاتحة.

**ما تم:**
- الهيدر والبار السفلي وشاشتَي الدخول/التسجيل صاروا **يتبعون الثيم المختار**. `navBackground` بالفاتح = بلاطة بيضاء (ورق) مع حدّ رفيع.
- خلفية التوهّج (`PromooGlowBackground`) صارت theme-aware. الشاشات الغامرة فقط (السبلاش، عارض الستوري/الميديا) بقيت غامقة دائماً.

**التحقق:** analyze نظيف · تحقّق بصري للثيمين على كل التبويبات.

## المرحلة 3 — الأيقونات + اللوغو + بطاقة الترحيب + زر الثيم

**المطلوب:** توحيد أيقونات الهيدر بشكل التطبيق القديم (فحص `Projects-Pictures` بكسل‑بكسل)؛ إضافة قسم ترحيب لصفحة البروفايل (صورة المستخدم + "Hi {الاسم}, Welcome to Promoo")؛ إصلاح اللوغو (إزالة المستطيل، لوغو فاتح مخصّص `promoo4.v.png`، وإبقاء الدارك الأصلي بلا صندوق)؛ إضافة أيقونة تبديل ثيم لشاشات الدخول (Home/Login/Register).

**ما تم:**
- فحص الصور بـ Pillow (تكبير) → اكتشاف أن أيقونة الشات القديمة **فقاعتان متراكبتان** → `PromooChatIcon`.
- **إزالة "ink-stamp"** (المستطيل الأسود حول اللوغو) نهائياً؛ `PromooLogo.full` يختار الصورة حسب الثيم (`promoo_wordmark.png` غامق / `promoo_wordmark_light.png` فاتح).
- **زر تبديل الثيم** (شمس/قمر) بالهيدر + إطار الـ auth.
- **بطاقة ترحيب** بصفحة البروفايل تستخدم صورة المستخدم الحقيقية (لا اللوغو).

> ملاحظة: لاحقاً بدّل المالك أيقونتَي الشات/الإشعارات إلى ملفات SVG (`assets/brand/icons/*.svg`) عبر الـ IDE — مُحترَمة.

**التحقق:** 195 اختبار (زيد اختبارات لوغو) · analyze نظيف · تحقّق بصري.

## المرحلة 4 — التحليل العميق وتقرير الربط

**المطلوب:** فهم الباك (تحليل فقط)؛ فحص الموبايل وتعبئة أي صفحات ناقصة؛ تقرير مفصّل: ربط كل section بالـ API، العدد الإجمالي، نسبة التوافق، نواقص الباك، وتحديد المؤجَّل لـ v2.

**ما تم:**
- **وكيلان متوازيان** (Explore/general-purpose): جرد عقد الباك الكامل (من `promoo-api-reference.json` + `routes` + `Apis-Resaults`) + جرد طبقة بيانات الموبايل حقلاً بحقل. + فحص التنقّل يدوياً.
- **[integration_map.md](integration_map.md)**: 111 endpoint، ~50 لـ v1، **~89% توافق** (محسوب حقلاً بحقل)، نواقص الباك، ترتيب الربط.
- **اكتشاف مهم (وقتها):** التطبيق كان أصلاً مربوطاً بالـ endpoints الحقيقية (`useMocks` افتراضي false) — الفجوة كانت سباكة المصادقة، لا بناء طبقة البيانات.
- **صفحات ناقصة: صفر** — كل الـ 23 مسار تفتح شاشة حقيقية.
- **رُصد تعارض منطقي:** صف "Add New Offer" يفتح wizard الإعلان (تعارض اسم/فعل/صلاحية).

## المرحلة 5 — إصلاح تعارض Add Offer/Ad + الـ role-gating + الشاشات الاختيارية

**المطلوب:** "صلّح التعارض" + بناء الشاشات الاختيارية (Add Offer منفصلة / Add Service / See-All) عبر sub-agent بالتوازي.

**ما تم:**
- `accountCapabilitiesProvider` (`features/profile/presentation/controllers/account_capabilities.dart`) يقرأ `account_type` من جلسة الـ auth ويشتقّ الصلاحيات (يطابق `requireAccountType` بالباك: Offer=company/service_provider · Ad=company/influencer · Service=company/service_provider · guest/user=لا شيء).
- قائمة البروفايل صار فيها **3 صفوف إنشاء منفصلة مُقيَّدة بالدور** بدل الصف الواحد المضلِّل.
- **sub-agent** بنى 3 شاشات (frontend-only): `add_offer_screen.dart`، `add_service_screen.dart`، `home_see_all_screen.dart` — ورُبطت بالراوتر + أزرار "See All" بالهوم.

**التحقق:** 200 اختبار (5 جداد للـ gating) · analyze نظيف · الشاشات الثلاث تحقّقت بصريّاً حيّاً.

## المرحلة 6 — إعادة الضبط: مسح كل الربط (frontend-only)

**المطلوب:** التطبيق مربوط فعلاً بالـ API، والمالك لا يريد ذلك الآن → **مسح كل الربط بلا أثر**، ليُبنى الربط لاحقاً جزءاً‑جزءاً على أساس نظيف.

**ما تم (حذف بلا أثر):**
- حُذفت طبقة الشبكة `lib/core/network/*` (ApiClient, Dio, ApiResponse, ApiException, ApiEndpoints).
- حُذفت كل `*_remote_data_source.dart` (9 ملفات) + `lib/core/config/app_environment.dart`.
- أُزيل `dio` من `pubspec`، وأُزيلت حقول `useMocks`/`baseUrl`/`environment` من `AppConfig` (بقي `fallbackCurrency` فقط).
- كل `*_repository_impl.dart` صار **fake فقط** (بلا تفريع remote/mock)؛ الـ fakes ترمي `AppFailure` مباشرةً بدل `ApiException` المحذوف.
- حُذفت 11 اختباراً تختبر السباكة المحذوفة (9 repo + api_response + app_config)؛ أُصلحت 5 اختبارات شاشات كانت تمرّر `AppConfig(useMocks:…)`.
- **مُبقىً كتخزين محلي (ليس API):** `flutter_secure_storage` (حفظ الثيم)، `AuthSessionStore` (جلسة وهمية بالذاكرة).

**التحقق:** **160 اختبار يمرّ** · analyze + format نظيف · التطبيق يقلع ويشتغل كلّياً على بيانات محلية.

## المرحلة 7 — تدقيق قائمة تعديلات الزبون (2026-07-10)

**المطلوب:** قائمة تعديلات فرونت من الزبون، كل بند موسوم `done`/`check`/`fix`. المطلوب التحقق من الكل، وإصلاح بنود `fix` والـ`check` غير المكتملة.

**التحقق (شغّال أصلاً):**
- **صفحة الخدمات:** بحث + شبكة تصنيفات بصور حقيقية + حالة "No service found". ✓
- **صفحة الإنفلونسر (المقاعد):** شريط مضغوط "N Influencers / M Available seats" + مفتاح الفئات Gold/Silver/Bronze + شبكة مقاعد ملوّنة بالفئة — مطابقة للتصميم القديم. ✓
- **بروفايل عام بأسلوب إنستغرام:** Followers/Likes/Posts/Views عبر `profile_stats_row.dart`. ✓
- **Top Offers:** 5 شرائح hero. ✓

**الإصلاحات:**
1. **"See All" في Promoo of the Day:** صار ينقل فعلياً (`AppRoutes.homeSeeAll('offers')`) بدل إشعار المعاينة.
2. **تبديل الفوتر:** علامة الـ P المركزية صارت تفتح صفحة Cup وتُسمّى "Promoo"؛ Services صارت تبويباً عادياً (الترتيب: Home·Influencer·[P]·Services·Profile). حُدّث `_selectedIndexForPath` ودلالات `_CenterPMark` واختبار الـ shell.
3. **زجاجية الهيدر عند التمرير (#5):** هيدرات التبويبات كانت مثبّتة على `isScrolled:false`. أُضيف `shellScrolledProvider` (Notifier — **StateProvider غير مُصدَّر في Riverpod 3.x هنا**) يقوده مستمع التمرير الموجود بالـ shell (مصدر واحد للفوتر والهيدر، يُصفَّر عند تبديل التبويب). صار `PromooPageHeader.isScrolled` قابلاً للـ null → يرجع للـ provider. حُوّلت شاشات Services وCup وProfile-menu إلى هيدر `SliverPersistentHeader` مثبّت (delegate مشترك `PromooPinnedHeaderDelegate`) بحيث يمرّ المحتوى **تحت** الهيدر لتأثير زجاجي حقيقي متل Home. صفحة المقاعد تبقي شريط البحث/الفئات ثابتاً (مطابقة للقديم) فيبقى هيدرها لوناً متفاعلاً فقط.

**التحقق:** 160 اختبار يمرّ · analyze نظيف · تحقّق حيّ (Cup: المحتوى يمرّ تحت الهيدر ويتزجّج عند التمرير؛ الفوتر بالترتيب الجديد).
